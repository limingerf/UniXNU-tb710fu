fix(0053): noinline recorder with string tags so no branch can vanish

Round 42 found that the pl107 image contains the probe ring symbol but NOT the
openat and fcntl tag immediates:

    OATN 0x4F41544E  hits=0   (every byte offset checked)
    FNCT 0x464E4354  hits=0
    MMAP 0x4D4D4150  hits=16  (all inside unrelated strings)
    MUNM 0x4D554E4D  hits=6   (same)

The MMAP/MUNM "hits" turned out to be text inside 'SKR_MODE_MMAPOK' and
'eSMART_MMAP_KERNEL_FLAGS_TRIALS', so they were not evidence at all. The two
genuine zeros meant the helper was inlined and at least two switch arms were
eliminated -- precisely the two calls that matter: openat names the file, and
fcntl(0x61 = F_ADDFILESIGS_RETURN) names the fd being signed.

Three changes to make the recorder unremovable and verifiable:

  __attribute__((noinline))  the function now leaves a symbol, so presence can
                             be checked by name instead of by hunting for an
                             immediate that a backend may assemble with movz/movk
  two memory clobbers        stop reordering or elimination around the stores
  string tags                a 4-byte literal can be folded or split; a byte
                             string cannot, and it stays greppable in the image
